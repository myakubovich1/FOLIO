# Folio shared project brief
Goal: finish the original docs/requirements.md product brief: permissioned source records → review/correction → explainable deterministic credit assessment → versioned passport/PDF → controlled sharing/revocation. US/USD and Kenya/KES demos need no traditional credit file. Never imply lender acceptance or empirical predictive validity.

Codex owns architecture, implementation, integration and checks. Claude is the sole independent read-only reviewer, reviewing stable Git exports. No additional agents or orchestration framework. Both receive this brief and docs/assessment.md explicitly. Previous initial-slice limitations are work to complete, not reasons to skip implementation bugs.

Architecture: Next.js App Router React interface, a co-hosted Express API to preserve tested business logic during migration, Auth0 official Express OpenID Connect SDK (authorization-code flow), Tiger Data/Postgres repository with a Timescale transaction hypertable and continuous aggregate. SQLite is an explicit local/demo adapter, never a silent failover from a configured database. `server/index.ts` mounts API/auth before Next's request handler. `server/app.ts` accepts an injected trusted-identity adapter only for automated factory tests; production never accepts client identity headers.

Contracts: src/contracts.ts defines records (source/category/status/provenance), borrower coverage/balance/obligation evidence, assessment, passport, sources, revisions and explanations. server/assessment.ts alone performs score math. Store transactions scope reads/writes to authenticated owner or isolated random synthetic session. Owner ID is never accepted from request payloads. Share tokens are hashed and snapshots immutable; recipient responses exclude identities and raw records. Owner deletion must remove derived rows and revoke shares, and every export route must enforce the same boundaries as its snapshot route.

In-progress checkpoints: first migrate shell/storage and authentication boundaries while preserving borrower demo; next finish uploads/provenance/PDF; then providers, evidence explanations/scenarios and UX. docs/completion.md tracks all requirements. Credential variables are absent until entered locally through ignored .env.local; docs/configuration.md contains the consolidated setup. Auth0, Tiger Cloud, Nessie and Gemini are not verified live merely because adapters exist. Local TimescaleDB is used for SQL correctness when available.

Checks: unit financial/ingestion tests, owner/demo/recipient isolation, expiry/revocation including PDFs, invalid AI evidence/numbers/injection tests, desktop/mobile/keyboard browser flows, PDF render inspection, lint/typecheck/build. Record exact reviewed commits, findings/dispositions and verified/externally blocked outcomes under reviews/ and docs/.
