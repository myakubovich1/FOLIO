# Import format and correction

Download an exact synthetic example from Records → Upload statement; files are also in samples/. A public demo accepts only these exact generated samples. Private owners can upload their own CSV/PDF after authentication and informed consent. PDF extraction requires configured Gemini and explicit provider permission. CSV maximum1MB/5,000rows; PDF maximum4MB/10pages. No raw file is saved to disk by the application.

CSV uses signed major-unit decimal amounts (e.g. -10.05), exactly two decimal places at most, no exponent/thousands separators; server stores integer cents/minor units. One account alias and supported USD/BYN currency per file. Never enter a full account number as the alias. Stable id is required across overlapping exports. Required row fields: id,date,amount,currency,category,description,account_id. Dates must be real YYYY-MM-DD inside the end-exclusive coverage period. Categories: income,expense,transfer,borrowing,refund,unknown. Missing/unsupported categories stay unknown and must be reviewed. Withdrawals are deliberately unknown until cash purpose is confirmed.

Statement metadata (identical on each row): account_type checking/savings/mobile-money/credit/unknown; coverage_start,coverage_end (day after last covered day),coverage_complete true/false,opening_balance,closing_balance,obligations_documented true/false. These are user-provided document fields, not provider authentication. Missing complete coverage, balance or obligation evidence blocks a score. Credit/unknown account types do not establish liquid reserves. Never invent a zero balance, no obligations or complete history to obtain a score.

Optional row fields: status posted/pending (default posted),record_type transaction/bill/invoice/payment/mobile-money/withdrawal,linked_record_id. A bill is obligation evidence, not a cash movement; link its actual payment. Pending invoices are not earnings. Linked duplicate payment/underlying movement is counted once. Internal transfers and borrowed funds are never income. Refunds reduce expenses. Every unresolved posted movement can require clarification; unrecorded cash use stays unknown.

Preview reports invalid rows, exact balance reconciliation, duplicates and unresolved classifications before commit. Reconcile opening + posted raw movements to closing balance. A failed reconciliation may be imported for review but remains unscored. Correct malformed dates/amounts/coverage in the original file, then preview again; existing records stay unchanged on failed commit. For classification corrections after import, use Records; original values and before/after revisions remain. Re-import does not undo those corrections. Conflicting IDs are rejected, not silently overwritten. Overlapping periods merge stable IDs, coverage gaps abstain, and every account must cover the common period with reconcilable balances.

Source disconnect stops future ingestion and preserves historical evidence; reconnect requires explicit permission. Whole-workspace deletion removes raw/derived application data and sharing access. The app does not promise immediate deletion from provider storage/backups. Parsed uncommitted previews expire after15minutes and are cleaned within the next minute while the service runs.
