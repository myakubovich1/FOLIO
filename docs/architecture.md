# Architecture and interfaces

Next.js App Router hosts the React client. Express owns API/authentication and calls Next for page requests (`server/index.ts`). This preserves independently testable server modules. The custom server requires a Node/container host; it is not a Vercel serverless/Next standalone build. Auth0 Universal Login supplies authorization-code identity through its official Express SDK. Only the test factory accepts a trusted injected verifier; the production entry never trusts identity headers.

`src/contracts.ts` is the shared wire contract. Money is integer minor units and every calculation has one currency. `server/assessment.ts` is deterministic and contains no model calls. `server/workspace.ts` snapshots the model configuration. Assessment revisions change when financial interpretation/context changes. Immutable passports retain the exact result and config even when later inputs change.

Ingestion boundaries: `imports.ts` exact decimal parsing, dates, stable IDs, reconciliation, deduplication and coverage; `upload-routes.ts` owner-scoped consent/preview/commit; `nessie.ts` scoped synthetic resources and reported capabilities. PDF extraction is model-suggested and requires preview confirmation. Corrections retain original values and append before/after interpretation history. CSV source metadata is user-provided, not authenticated bank verification. Checking/savings/mobile-money are potentially liquid; unknown/credit accounts cannot provide scoring liquid balance evidence. Each account must cover the common observation period; no gaps are silently filled.

Tiger/PostgreSQL is the configured source of truth. `Store` persists normalized records to a Timescale hypertable, a partition-compatible registry, immutable assessment revisions and scorecard versions, plus owner-scoped JSON workspaces/sources, consent, ingestion/correction history, snapshots, hashes, previews and event-only audit entries. Operational state is intentionally compact rather than a microservice system. Market config is included in assessment JSON. Accounts use hashed aliases inside normalized source/record data. Current factor contributions/reason codes/references are in each assessment revision. No raw source file is saved.

`/api/cashflow` refreshes a bounded date range and reads the real daily continuous aggregate grouped into numeric monthly rows, scoped by owner/currency. Excluded bill evidence and pending movements are ignored. Corrections become visible on the next dashboard request. PG writes use an owner advisory lock and transaction; local mutations share a queue. Deletion is queued, cascades dependent rows, removes raw hypertable rows, refreshes aggregates, and retains a financial-data-free hashed tombstone to prevent implicit resurrection. Dashboard queries require a live workspace and no tombstone. Startup finishes pending deletion cleanup. Historical records are intentionally retained on disconnect; future ingestion requires explicit reconnection.

AI: owner-authorized current state is retrieved through Store (Tiger when configured), then typed read-only evidence tools minimize the bundle. Gemini receives structured schema inputs. It selects supported explanation kinds and IDs; the server renders all prose and financial numbers from named metrics. It cannot invent numerical text, call another owner's tools, approve loans or write calculations. Classification/pattern outputs are suggestions requiring human confirmation. Revision guards reject stale results. No OpenAI product API is used for application functionality; Codex is the builder only.

Shares: random 256-bit opaque tokens; only SHA-256 hashes stored. Every JSON/PDF lookup checks expiry/revocation. Recipient responses are whitelist snapshots without identity, account IDs, raw merchant history, monthly detail or raw evidence IDs. Disclosure toggles remove actual fields. Private PDF paths resolve only against the authenticated owner's snapshots. Browser, API and share pages use no-store/noindex/no-referrer. Audit records permitted service accesses as events, without asserting viewer identity or exact person counts.

Data retention: raw upload buffer in request memory; parsed preview expires at 15 minutes and is removed within the next minute while running (or at subsequent cleanup). Confirmed data remains until deletion. Public synthetic sessions expire after seven days; their retained synthetic workspace is removable with Settings. No immediate external-provider or backup erasure is promised. Production operators must define backup retention, legal purpose, provider processing and deletion procedures before using real financial records.

Provider budgets now use atomic database counters, with per-owner and shared API-key-hash ceilings. A rotating public session cannot multiply the shared logical-operation ceiling. They do not rewrite the ledger or claim to match vendor quota units. SDK/API attempts remain bounded; Nessie synchronization has a30-second overall request budget. Optional public Nessie access is only for a dedicated synthetic customer, never owner uploads or arbitrary customer IDs. Deletion may report analytics cleanup pending while access remains denied; explicit recreation safely retries cleanup after service recovery without overriding the tombstone.
